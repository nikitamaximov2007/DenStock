# PRO-STOR: вход для нового чата

Актуальность проверять по Git и источникам задачи; снимок этой документации
создан 18.11.2026. DenisStock: Django-система склада и продаж запчастей;
PRO-STOR: публичный каталог и направление продвижения продукта для сервисов.
Код использует `denstock`, PostgreSQL в production и SQLite в разработке,
Docker Compose и Caddy. Доменные приложения перечислены в
[настройках](../config/settings/base.py), маршруты в [config/urls.py](../config/urls.py).

Начать с [ROADMAP](ROADMAP.md), [правил AGENTS.md](../AGENTS.md),
[протокола совместной работы](development/ai-collaboration.md), затем читать
документацию и код конкретной задачи. Для монтажа R10 начать с
[R10_MASTER](marketing/reels/R10/R10_MASTER.md) и [handoff](development/r10-knowledge-handoff.md). История: git log, документы
задачи, связанные ветки и handoff. [Current handoff](development/current-handoff.md)
относится к конкретной ветке и моменту: не считать его автоматически актуальным
для любой задачи. Старые чаты и локальные медиа не появляются в Git автоматически.

Перед работой последовательно выполнить `git status --short`, `git branch
--show-current`, `git log --oneline --decorate --max-count=5`; проверить remote,
worktrees и реальный базовый SHA. Не перезаписывать чужие изменения, не объединять
ветки без основания. Для независимой работы создать отдельные ветку и worktree
от проверенного `origin/main`, соблюдая протокол. Не переключать занятую ветку.

`main` содержит проверяемую основу восстановления, но текущий production может
временно отличаться: фиксировать подтверждённые SHA отдельно для репозитория и
образов; после принятого релиза согласованно fast-forward в `main` без переписи
истории. Ни `main`, ни локальная ветка сами по себе не доказывают runtime SHA.

Остатки изменяются только установленными потоками проведения документов; черновики
и импорт не меняют остатки. Деньги через Decimal, клиентские цены BRP через
`catalog_part_price_rub`; правила адресов и сохранения истории в AGENTS.md.
Не публиковать секреты, клиентские данные, бэкапы и локальное медиа. Этот remote
публичный: всё отправленное в любую ветку или PR публично. Не подключаться к
production и не выполнять deployment без отдельной задачи и разрешённой области.

После значимого этапа обновить roadmap, профильный документ и журнал решений,
зафиксировать следующий шаг, коммитить и публиковать согласованную безопасную
часть обычным Git-процессом. Замечания по R10 вносить в R10_DECISIONS и при
необходимости в timeline. Сохранять историю Git, подтверждённое отличать от гипотез.
