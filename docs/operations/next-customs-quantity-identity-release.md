# Следующий релиз: Excel таможни, количество заказной детали, identity образа

Статус: кандидат, production не изменён. База кода: `df50ecb290efb47f68d8680b7add3b51aa2f553b`.
Целевой SHA берётся из подтверждённого владельцем коммита ветки
`codex/next-release-customs-quantity-identity`; сверять полные 40 символов с
`git rev-parse HEAD` и удалённой веткой перед каждым шагом. Не использовать
имя ветки как идентификатор развёртываемого кода.

## Состав и границы

- Миграция: `ordered_parts.0002_orderedpart_quantity_orderedpart_request_token_and_more`.
  Исторические записи получают количество 1. БД сохраняет default 1 для
  старого кода; новые записи ограничены диапазоном 1..10000.
- Приложение: меняется только web. Telegram, MAX, catalog-web, PostgreSQL и
  Caddy не пересоздавать. Новый Compose описывает SHA-идентификацию всех
  четырёх приложений, но для этого выпуска собирать и менять только web.
- Предоплата остаётся одной введённой суммой. Создание заказной детали не
  создаёт складских движений. Таможенный источник использует её количество.
- Уже включённое в таможенный заказ количество нельзя исправлять. Зафиксированные
  состав, курс и сумма исторического заказа не пересчитываются.

## Карта исходного XLSX

| Столбец | Источник | Преобразование |
| --- | --- | --- |
| A: трекинг | нет автоматического источника | пусто, вводится вручную |
| B: артикул | `CustomsOrderLine.article` | текст, пунктуация и ведущие нули сохранены |
| C: название RU | `name_ru`; при пустом снимке версия того же `PartType`, подтверждённое поле или проверенный словарь | верхний регистр, неизвестное остаётся пустым |
| D: название EN | `name_en`; при пустом снимке версия или точная связь с каталогом | верхний регистр, неизвестное остаётся пустым |
| E: производитель | `manufacturer` | исторический снимок, верхний регистр |
| F: страна | `country` | исторический снимок, неизвестное остаётся пустым |
| G: брутто за штуку | `gross_weight_kg` | кг, минимум 0.03 только в Excel; неизвестное пусто |
| H: нетто за штуку | `net_weight_kg` | кг, минимум 0.03 только в Excel; неизвестное пусто |
| I: брутто всего | G, J | `=Jr*Gr` только при известном G; итог пуст при неизвестном весе |
| J: количество | `quantity` | исторический Decimal, числовая ячейка |
| K: цена за штуку | `wholesale_usd` | историческая оптовая цена USD, числовая ячейка |
| L: стоимость всего | K, J | `=Kr*Jr` только при известной цене |
| M: применение | `application_area` | исторический снимок, неизвестное пусто |

`CustomsOrder.fx_rate`, `total_rub` и `CustomsOrderLine.rub_amount` хранят
исторические рублёвые значения. Исходный шаблон не имеет отдельной колонки
для них: не добавлять её без утверждения формы. При пустом снимке названия
экспорт читает данные справочника без записи в БД. Неизвестные веса, страну и
перевод не придумывать. Аномальные исходные веса проверять отдельно вручную;
экспорт не исправляет их молча.

## PRE и разрешение

1. Согласовать тихое окно и явно подтвердить отсутствие складских операций.
   Проверить фактический код web внутри контейнера, image ID, checkout,
   миграции, здоровье сервисов, место, общий backup lock и ночное расписание.
   Старая переменная `DENSTOCK_APP_COMMIT` в `.env` не доказывает runtime SHA.
2. Создать свежий полный подписанный PRE без capped wrapper и без ротации:
   PostgreSQL, `media`, `private_media`. Использовать общий
   `/run/lock/denstock-backup.lock` и однократный `backup_all` без
   `--keep-last`. Передать только зашифрованный age-архив на Mac. Проверить
   Ed25519, SHA-256, состав, ссылки на файлы и восстановление в изолированной
   PostgreSQL 16. Сохранить прежние поколения и образы.
   Проверенная процедура шифрования и передачи находится в
   `docs/operations/private-media-single-bucket-mac-release.md` коммита
   `12676dd852161dfe6f79c0d75f6eaac6e23e3306`; сам файл не подмешивать
   из другой ветки в этот выпуск. Однократный запуск без ротации:

   ```bash
   (
     exec 9>/run/lock/denstock-backup.lock
     flock -n 9 || exit 75
     docker compose exec -T -e DENSTOCK_APP_COMMIT=<проверенный-runtime-SHA> \
       web python manage.py backup_all --trigger manual
   )
   ```

   Эта команда не запускает entrypoint и миграции. Run ID сверить по выводу,
   затем `docker compose exec -T web python manage.py verify_backup <RUN_ID>`.
   Старые копии не очищать; обычный capped wrapper не вызывать.
3. Остановиться. Получить отдельное разрешение владельца на точный целевой SHA,
   миграцию и обновление web.

## Установка после отдельного разрешения

1. Снова проверить тихое окно, SHA, миграции, здоровье и отсутствие backup.
   Сохранить текущий image ID и действующие Compose overlays:
   `docker-compose.yml`, `deploy/ai-support/docker-compose.external.yml`,
   `docker-compose.signing.yml`. Не выводить полный Compose config, env или
   secrets в логи.
2. Переключить checkout на одобренный точный SHA. Сборку web выполнить через
   `scripts/operations/release_image_identity.py build --sha <SHA> --services web`.
   Инструмент строит из точного Git archive и проверяет OCI revision,
   source-archive SHA-256, image ID и встроенный `DENSTOCK_APP_COMMIT`.
3. В рамках одобренного релиза убрать только устаревший ключ
   `DENSTOCK_APP_COMMIT` из production `.env` и указать
   `DENSTOCK_BUILD_REVISION=<SHA>`. Не раскрывать остальные значения. До
   пересоздания запустить `release_image_identity.py verify --sha <SHA>
   --services web`. Ошибка identity останавливает выпуск.
4. Обновить только web командой `docker compose up -d --no-build --no-deps
   --wait web`. Штатный entrypoint применяет миграции. Отдельно `migrate`
   не запускать. Если миграция прервалась, не поднимать старый web на частичной
   схеме и не откатывать схему вслепую.

## POST и критерий успеха

Проверить `verify --runtime` для web, фактический исходный код образа,
`ordered_parts.0002`, `/healthz/`, HTTPS склада и `pro-brp.ru`, анонимный 404
приватного вложения, сохранность остатков и документов. Из production можно
без записи открыть историю таможенного заказа и форму заказной детали; не
создавать реальные тестовые заказы. Проверить, что Telegram/MAX и catalog-web
остались на прежних контейнерах и здоровы.

Затем создать отдельный полный подписанный POST без ротации, зашифровать age на
Mac и восстановить PostgreSQL 16, `media` и `private_media` в изоляции.
Проверить подпись, хеши и ссылки. Только после успешного восстановления POST
отчёт может иметь статус SUCCESS.
Для POST использовать тот же lock и однократный `backup_all`, подставив уже
проверенный новый runtime SHA; PRE и POST хранить раздельно и не перезаписывать.

## Ошибка и откат

Сохранить логи, прежние образы, PRE и POST. Не выполнять разрушительный
down-migrate и не восстанавливать старую БД без отдельного решения владельца.
Схема после миграции совместима со вставкой старого кода благодаря DB default,
но старый код считает каждую новую заказную запись одной единицей в таможне.
После появления заказов с количеством больше 1 откат только к `df50ecb`
искажает отчёты. В таком случае предпочтителен исправленный новый образ;
временный откат требует остановки соответствующих операций и явной оценки
данных. Не пересоздавать ботов, каталог, proxy и PostgreSQL ради отката web.
