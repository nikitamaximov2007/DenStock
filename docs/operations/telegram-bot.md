# Telegram-бот заявок клиентов: эксплуатация

Документ для владельца и администратора. Архитектура и гарантии описаны в
[docs/design/customer-request-telegram.md](../design/customer-request-telegram.md).
Реальные токены, пароли и Telegram ID сотрудников в этот файл не вписываются.

## Что делает бот

- Клиент выбирает в каталоге «Telegram», отправляет заявку и сразу видит номер
  заявки. Заявка создаётся в DenisStock в любом случае, даже если Telegram
  недоступен или бот выключен.
- На странице успеха есть кнопка «Продолжить в Telegram». Она открывает бота с
  одноразовой ссылкой. После «Запустить» бот связывает чат клиента с заявкой.
- Сотрудники получают в боте карточку новой заявки, сообщения клиента и
  отвечают кнопкой «Ответить». Клиент видит ответ от имени бота PRO-STOR.
- Вся переписка хранится в карточке заявки: раздел «Переписка Telegram».

## 1. Создание бота в BotFather

1. В Telegram откройте `@BotFather`, команда `/newbot`.
2. Имя (видно клиентам): например `PRO-STOR`.
3. Username бота: латиница, оканчивается на `bot`, например `prostor_zayavki_bot`.
4. BotFather выдаст **токен**. Это секрет уровня пароля: не пересылайте его в
   чаты, письма и ИИ-ассистентам.
5. Рекомендуется: `/setjoingroups` → Disable (бот работает только в личных чатах).
6. По желанию: `/setdescription`, `/setuserpic`.

Владельцу нужны два значения: **токен** и **username бота** (без `@`).

## 2. Безопасная настройка на сервере

На сервере в `/opt/denstock`:

1. Создайте файл только для бота (токен не попадает в `web` и `catalog-web`):

   ```
   umask 077
   printf 'TELEGRAM_BOT_TOKEN=%s\n' '<вставьте токен вручную в терминале>' > .env.telegram
   chmod 600 .env.telegram
   ```

   Файл не коммитится (`.env.*` в `.gitignore`) и должен пережить каждый deploy,
   как `docker-compose.signing.yml`.
2. В `.env` (internal) добавьте:
   - `TELEGRAM_BOT_USERNAME=prostor_zayavki_bot`
   - `TELEGRAM_INTERNAL_BASE_URL=https://<внутренний адрес DenisStock>`
3. В `.env.public` (catalog-web) добавьте только
   `TELEGRAM_BOT_USERNAME=prostor_zayavki_bot`. Токен туда не пишется: публичный
   процесс принудительно обнуляет его в настройках.
4. Не задавайте `TELEGRAM_WEBHOOK_SECRET` и не включайте webhook у бота: V1
   работает через long polling.

## 3. Запуск сервиса telegram-bot

Сервис включается отдельным профилем и не стартует вместе с обычным deploy.

```
docker compose --profile telegram-bot up -d --build --no-deps telegram-bot
docker compose --profile telegram-bot ps telegram-bot
docker compose --profile telegram-bot logs --tail 50 telegram-bot
```

Порядок при выпуске: сначала обновить `web` (он применяет миграции), затем
`catalog-web`, затем `telegram-bot`. Бот отказывается стартовать, если есть
непримененные миграции.

Проверка: страница DenisStock «Заявки клиентов» → «Telegram-бот» показывает
«Работает · @username», время последнего обновления и очереди.

Здоровье контейнера: бот обновляет файл-сигнал каждый цикл; healthcheck
считает контейнер нездоровым, если сигнала нет больше 90 секунд.

**Только один экземпляр.** Никогда не запускайте второй `telegram-bot` с тем же
токеном (второй сервер, `docker compose run`, локальный запуск с боевым
токеном). Защита: блокировка PostgreSQL, аренда в базе и ответ Telegram 409.
Второй экземпляр завершается с сообщением «Другой экземпляр Telegram-бота уже
работает». Не используйте `--scale telegram-bot=2`.

## 4. Как сотрудник узнаёт свой Telegram ID

1. Сотрудник открывает бота и пишет `/whoami`.
2. Бот отвечает только его собственным числовым ID. Данных заявок бот
   посторонним не показывает.
3. Сотрудник передаёт это число администратору.

## 5. Как дать сотруднику доступ

1. У сотрудника должна быть учётная запись DenisStock с доступом к заявкам
   клиентов (роль Продавец/Мастер, Руководитель или Администратор).
2. DenisStock → «Заявки клиентов» → «Telegram-бот» → «Добавить сотрудника».
3. Выберите пользователя, введите Telegram ID, роль, «Добавить».
4. Сотрудник пишет боту `/start`: появится меню и команда `/requests`.

Один Telegram ID нельзя привязать к двум пользователям. Авторизацию бот
проверяет заново на каждом сообщении и каждой кнопке.

## 6. Как отозвать доступ

- «Telegram-бот» → «Отключить» у сотрудника. Действует сразу: следующие
  сообщения и кнопки этого сотрудника отклоняются, неотправленные ему
  уведомления не отправляются.
- Отключение пользователя DenisStock или снятие роли с доступом к заявкам тоже
  немедленно закрывает бота.

## 7. Поведение ссылки клиента

- Ссылка `https://t.me/<бот>?start=<одноразовый токен>` не содержит номер
  заявки, телефон или ID. В базе хранится только SHA-256 токена.
- Срок жизни `TELEGRAM_REQUEST_LINK_TTL_SECONDS` (по умолчанию сутки). Ссылка
  одноразовая: повторное открытие другим человеком отклоняется.
- Если клиент не открыл бота, заявка остаётся обычной: менеджер звонит по
  телефону. Новую ссылку можно выдать в карточке заявки («Создать ссылку
  Telegram»), старые при этом отзываются.
- Если у клиента несколько заявок, последняя подключённая становится активной.
  Команда `/requests` у клиента показывает только его собственные заявки и даёт
  выбрать нужную. При неоднозначности сообщение не сохраняется, пока клиент не
  выберет заявку.
- В V1 бот принимает только текст. На фото он отвечает, что пока принимает
  текст. Приём фото и файлов оставлен на V2 (нужны приватное хранилище,
  лимиты и проверка содержимого).

## 8. Если Telegram недоступен

- Приём заявок не зависит от Telegram: заявка и уведомления сохраняются в базе.
- Бот повторяет отправку с нарастающей паузой (до 15 минут, до 8 попыток),
  учитывает `retry_after` от Telegram.
- Отказы без смысла повторять (например, клиент заблокировал бота) получают
  статус «Не доставлено». Если отправка оборвалась на полпути, сообщение
  получает статус «Неизвестно, доставлено ли» и **не отправляется повторно**,
  чтобы клиент не получил дубль. Такие случаи видны в карточке заявки и на
  странице «Telegram-бот»: свяжитесь с клиентом вручную.
- Telegram хранит неполученные обновления около суток: после восстановления
  связи бот их дочитает.
- Если бизнес-запись в базе заморожена (maintenance/аварийный режим), бот
  ставит обработку на паузу и не теряет обновления.

## 9. Перезапуск и восстановление

- `docker compose --profile telegram-bot restart telegram-bot`: бот доделывает
  текущий цикл (SIGTERM, до 40 секунд) и выходит.
- Обновление Telegram и его номер сохраняются одной транзакцией: после
  перезапуска ничего не теряется и не применяется дважды.
- Уведомления сотрудникам уникальны на пару «событие, сотрудник»: перезапуск
  не дублирует карточку новой заявки.
- При падении процесса аренда истекает через 90 секунд; `restart:
  unless-stopped` поднимет контейнер.

## 10. Смена (ротация) токена

1. BotFather → `/mybots` → бот → API Token → Revoke current token.
2. Старый токен перестаёт работать сразу; бот завершится с ошибкой 401.
3. Запишите новый токен в `.env.telegram` (как в разделе 2).
4. `docker compose --profile telegram-bot up -d --no-deps telegram-bot`.
5. Проверьте страницу «Telegram-бот». Username бота не меняется, ссылки
   клиентов остаются рабочими.

## 11. Экстренная остановка бота

```
docker compose --profile telegram-bot stop telegram-bot
```

Заявки продолжают приниматься, уведомления копятся в очереди и уйдут после
запуска. Чтобы клиенты не видели кнопку Telegram, уберите
`TELEGRAM_BOT_USERNAME` из `.env.public` и перезапустите `catalog-web`: страница
успеха напишет, что Telegram сейчас недоступен и менеджер позвонит.

Если токен мог утечь: сначала отзовите его в BotFather (раздел 10).

## 12. Откат выпуска

- Код: `git checkout` предыдущего SHA, `docker compose --profile public-catalog up -d --build --no-deps web catalog-web`,
  затем `docker compose --profile telegram-bot stop telegram-bot`.
- Миграции `customer_requests.0005_telegram_messaging` и
  `operations.0005_telegram_messaging` только добавляют таблицы и снимают
  ограничение уникальности чата. Старый код их не читает, откатывать схему не
  нужно. Если всё же требуется: остановить бота, затем
  `python manage.py migrate customer_requests 0004` и
  `python manage.py migrate operations 0004` (удалит историю переписки,
  сделайте бэкап).
- После отката кода перезапустите `create_public_catalog_role.sql`, чтобы
  публичная роль снова получила ровно прежний набор прав.
- Резервную копию PRE использовать только для восстановления данных.

## 13. Обновление прав публичной роли

Новые таблицы требуют повторного запуска скрипта ролей после миграций:

```
docker compose exec -T db psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -v ON_ERROR_STOP=1 -v public_role=denstock_public \
  -f - < scripts/operations/create_public_catalog_role.sql
```

Публичный процесс получает только INSERT (и чтение столбца id) в таблицы
переписки, события и одноразовой ссылки. Читать чаты, токены и сообщения он не
может.
