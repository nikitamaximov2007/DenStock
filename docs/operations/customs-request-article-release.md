# Отдельный выпуск: артикулы продаж по клиентским заявкам

База кандидата: `67b468a467cce81c1f2154b167791681d3171e76`.
Ветка: `codex/customs-request-sale-articles-20261022`. Перед выпуском оператор
подставляет в `TARGET_SHA` точный одобренный commit из отчёта о квалификации и
проверяет его родство с фактическим работающим SHA. Если production уже ушёл
вперёд, этот кандидат необходимо отдельно интегрировать и повторить проверки.

Изменение касается только чтения истории таможенных источников. Новых миграций,
складских движений и пересчёта старых документов нет. Обновляется только `web`.
Старые продажи из заявок получают артикул при чтении из сохранённой строки
заявки по точным `sale_id` и `part_type_id`. При отсутствии однозначного снимка
поле остаётся пустым. Уже зафиксированные таможенные заказы не переписываются.

## PRE и разрешение

1. Получить отдельное разрешение владельца на точный SHA и тихое окно. Проверить
   runtime image identity, здоровье всех контейнеров, текущие миграции, общий
   backup lock, свободное место и отсутствие незавершённого backup. Сохранить
   текущий `web` image ID и Compose overlays. Не выводить `.env` и секреты.
2. Создать полный подписанный PRE без capped wrapper и ротации по процедуре
   `docs/operations/private-media-single-bucket-mac-release.md`: PostgreSQL,
   `media`, `private_media`. Зашифровать age на Mac, проверить Ed25519 и SHA-256,
   восстановить PostgreSQL 16 и оба дерева файлов в изоляции. Сохранить PRE.
3. Сверить фактический работающий SHA и схему с базой кандидата. При расхождении
   остановиться. Получить отдельное разрешение на установку.

## Установка после разрешения

```bash
cd /opt/denstock
git cat-file -e "$TARGET_SHA^{commit}"
git merge-base --is-ancestor 67b468a467cce81c1f2154b167791681d3171e76 "$TARGET_SHA"
python3 scripts/operations/release_image_identity.py verify \
  --sha 67b468a467cce81c1f2154b167791681d3171e76 --services web --runtime
# Зафиксировать текущий image ID и overlays, затем переключить checkout
# на одобренный SHA по существующей production-процедуре.
python3 scripts/operations/release_image_identity.py build --sha "$TARGET_SHA" --services web
python3 scripts/operations/release_image_identity.py verify --sha "$TARGET_SHA" --services web
docker compose up -d --no-build --no-deps --wait web
python3 scripts/operations/release_image_identity.py verify \
  --sha "$TARGET_SHA" --services web --runtime
```

Не запускать `migrate` вручную: entrypoint уже проверяет миграции. У этого
выпуска новых миграций нет. Не пересоздавать PostgreSQL, `catalog-web`, Caddy,
Telegram или MAX. Сохранить прежний образ для совместимого отката.

## POST и контроль

- Проверить `/healthz/`, HTTPS склада и `pro-brp.ru`, анонимный 404 для
  приватного вложения, здоровье ботов и каталога. Проверить отсутствие новых
  миграций и неожиданных изменений остатков и документов.
- Без записи открыть список таможенных источников и убедиться, что у старой
  продажи из заявки с однозначным снимком появился артикул. Пустые номера без
  доказанного снимка допустимы. Не создавать настоящие тестовые продажи или
  таможенные заказы.
- Создать отдельный полный подписанный POST без ротации, зашифровать на Mac,
  проверить подпись, хеши и изолированное восстановление БД и обоих медиа.
  Сохранить PRE, POST и старые поколения.

При критическом сбое остановиться, зафиксировать фактическую схему, runtime SHA
и журналы. Не выполнять разрушительный откат или восстановление старой БД без
отдельного решения владельца. Поскольку схема не меняется, прежний образ `web`
может быть кандидатом для app-only rollback после проверки текущих записей.
