# Кандидат: безопасный порядок offsite-бэкапа

Этот кандидат меняет порядок операций в `backup_offsite.sh`:

1. создать и проверить локальный backup;
2. отправить новый run в offsite;
3. сравнить удалённое содержимое полным чтением через `rclone check --download`;
4. только после успешной проверки выполнить локальную ротацию.

Ошибка загрузки или read-back сохраняет старые локальные копии. Скрипт не
удаляет удалённые runs и не запускает `cleanup-hidden`; при заполнении облака
новый запуск завершится ошибкой, не вытесняя старые удалённые копии. Ротация
offsite должна выполняться отдельной процедурой после проверки нового run.

Ветка основана на производственном SHA `7f13b16`. Это отдельная обёртка-кандидат,
а не готовый выпуск private_media: её можно квалифицировать только вместе с
выпуском приложения, который включает `private_media.tar.gz` в подписанный
manifest. Установленная на production обёртка находится вне репозитория и не
меняется этой веткой. Нужны отдельные review, PRE backup и явное разрешение
владельца до любой установки или изменения расписания.

Проверка `rclone check --download` читает удалённые данные для побайтового
сравнения; это увеличивает сетевой трафик и время запуска. Следует отдельно
проверить поддержку команды и стоимость чтения на настроенном S3 remote в
изолированном тестовом бакете до установки.
