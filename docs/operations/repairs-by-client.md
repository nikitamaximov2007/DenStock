# Ремонты по клиентам

## Назначение

Отчёт находится в «Отчёты» -> «Ремонты по клиентам» и отвечает на три вопроса:

1. Каким клиентам выдавались детали в ремонт в выбранный период.
2. Какие детали и в каком количестве ушли конкретному клиенту.
3. Из каких проведённых ремонтных заказов сложилась строка детали.

Отчёт полностью read-only. Он не меняет заказы, остатки, движения или цены.

## Денежная семантика

Ремонтный заказ хранит историческую стоимость деталей для клиента и отдельно
их закупочную себестоимость. Цена работ, оплаты, чека и прибыли DenisStock не
хранит. Стоимость деталей участвует в «Итого с клиента» вместе с продажами;
себестоимость в этот итог не входит и остаётся ограниченной правом
`can_view_purchase_cost`.

Старые строки без снимка клиентской цены отображаются как «Не зафиксировано».
Система не подставляет текущую цену задним числом и не заменяет неизвестное
значение нулём.

## Идентичность клиента в отчёте

После появления справочника клиент это карточка, а не текст. Отчёт разделяет
два случая и никогда их не смешивает:

1. Документ связан с карточкой. Строка отчёта это КАРТОЧКА: группировка идёт по
   её идентификатору, поэтому переименование карточки не дробит строку, а
   показывается всегда текущее имя. Ссылка ведёт в историю этой карточки.
2. Документ не связан с карточкой (создан до справочника или оформлен свободным
   вводом). Строка отчёта это ИСТОРИЧЕСКАЯ ЗАПИСЬ по сохранённому имени, и она
   помечена «без карточки».

Такие строки не объединяются между собой, даже если имя совпадает: одинаковое
имя не доказывает, что это один человек. Тёзки с карточками тоже остаются
разными строками.

## Источник данных

В отчёт входят только заказы со статусом `COMPLETED`. Период применяется к
`RepairOrder.completed_at`, включая обе выбранные даты целиком. Черновики и
отменённые заказы не учитываются.

Клиентская сумма читается из `RepairIssueLine.customer_unit_price_rub`, а
себестоимость из `unit_cost_rub`. Это снимки, замороженные в момент проведения
заказа; последующие изменения landed cost и текущих цен исторический отчёт не
меняют. Завершённые возвраты вычитаются из количества, суммы клиента и
себестоимости.

Имя клиента берётся из `RepairOrder.customer_name` и очищается от пробелов по
краям. Пустые имена объединяются в отдельную строку «Без клиента»: создать
заказ без клиента через интерфейс нельзя, такая строка возможна только у
унаследованных записей.

Название и канонический артикул детали показываются из текущей карточки той же
детали, как и в отчёте по продажам. Количественные и стоимостные значения при
этом остаются историческими.

## Экраны

1. «Ремонты по клиентам»: клиент, число ремонтов, число уникальных артикулов,
   фактически использованные единицы, стоимость деталей для клиента,
   себестоимость выданного, дата последнего ремонта.
2. Карточка клиента: те же величины в разрезе деталей.
3. «Выдачи в ремонт»: отдельные строки с датой, количеством, исторической
   суммой для клиента и замороженной себестоимостью.
