# Перенос двух публичных вложений в приватный том: план без потерь

Ветка `claude/private-attachment-security` (база production `f7b8086`).
Ничего из этого на production не выполнялось.

## Состояние на 2026-10-12 (только чтение)

- Live Caddy отдаёт 404 на любой путь с сегментом `customer_requests` внутри
  `/media/` (HEAD, GET, регистр, `%2F`, `//`, `./`, `..`). Публичного доступа
  к вложениям сейчас нет.
- В публичном томе `media` лежат 2 вложения сообщений. Для каждого в
  приватном томе есть по 2 побайтно одинаковые копии под альтернативными
  именами (след старой версии reconcile); строки БД ссылаются на публичное имя.
- Приложение не строит публичных ссылок на вложения
  (`PrivateAttachmentStorage.url` запрещён) и читает приватную копию раньше
  публичной, поэтому копия под тем же именем подхватывается без изменения БД.

## Порядок (каждый шаг с отдельного разрешения владельца)

0. Предусловие: выпущен полный бэкап с private_media
   (`claude/private-media-backup-release`), иначе вложения после переноса
   окажутся только в одном томе без резервной копии.
1. Выпуск этой ветки на `web` (новая команда reconcile; Caddy-файлы в
   репозитории равны live, live-файл не меняется).
2. Сухой прогон: `python manage.py reconcile_message_attachments_private`.
   Ожидание: «только в публичном media: 2», «вероятных дублей: 4»,
   конфликтов 0, отсутствующих 0. Иначе стоп.
3. PRE-бэкап штатной службой, проверка подписи, дампа, чтения назад.
4. `--apply`: копии под тем же именем (временный файл, fsync, link без
   перезаписи), сверка SHA-256. Ожидание «скопировано: 2».
5. Проверка: для обеих строк `storage.open(name)` читает приватный файл,
   SHA-256 равен публичному; оператор открывает вложения в рабочем месте.
6. Новый подписанный бэкап: в `private_media.tar.gz` есть обе копии,
   чтение назад без различий.
7. `--apply --remove-legacy`: удаление публичных копий только если ВЕСЬ
   набор вложений присутствует в приватном томе и совпадает побайтно.
   Ожидание «удалено публичных копий: 2».
8. Проверка: публичных файлов нет, анонимный HEAD/GET по старому пути 404,
   вложения открываются, POST-бэкап с private_media.

Дубли под альтернативными именами (4 файла) не удаляются этим планом:
только отдельным решением после сверки SHA-256 с уже перенесёнными копиями.

## Откат

- До шага 7 откатывать нечего: публичные оригиналы на месте, приватные
  копии лишние, но безвредные.
- После шага 7 публичные копии есть в PRE-бэкапе (`media.tar.gz`) и в
  приватном томе (байт в байт); вернуть публичную копию не требуется,
  приложение читает приватную.

## Чего этот план не делает

Не меняет БД, не меняет live Caddy, не трогает остальные файлы томов, не
выводит имена файлов клиентов (команда печатает модель и первичный ключ).
