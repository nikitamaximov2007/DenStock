# Согласование Caddy guard для вложений

Production Caddy сейчас защищает `/media/customer_requests/` регистронезависимым
matcher с учетом кодированных разделителей. Ранее tracked Caddyfiles содержали
только точный регистрозависимый путь, а emergency конфигурация guard не имела.
Этот кандидат синхронизирует production, локальный и emergency конфиги с текущим
guard и тестирует его наличие.

Это защита маршрута, а не перенос данных: два старых вложения все еще лежат в
публичном `media` volume. До отдельного миграционного окна оставить originals
нетронутыми. Для каждого файла сначала сопоставить DB reference, размер и SHA-256;
копировать в private volume под прежним относительным именем, затем повторно
сверить hash и проверить, что приложение читает private copy. Создать и проверить
новый подписанный backup. Только после всех gate отдельным явным действием удалить
публичную копию и проверить анонимный 404 на ее исходном URL. При любом конфликте
оставить обе копии и остановить перенос.

Ветка не обновляет production Caddy и не трогает реальные вложения. Перед будущей
установкой нужно сверить полный live Caddyfile с target, сохранить PRE-копию,
валидировать конфигурацию и затем отдельно перезагрузить Caddy по одобренному
runbook.
