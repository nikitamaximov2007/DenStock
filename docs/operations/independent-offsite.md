# Независимая ежедневная копия у второго провайдера

Зачем: ночная копия в Yandex защищает от потери VPS, но не от потери
аккаунта Yandex или одновременной потери VPS и Yandex. Независимая копия
лежит у другой компании, зашифрована на сервере ключом владельца и
проверяется чтением назад.

Состояние на 2026-10-13: скрипты и тесты готовы (против MinIO), на
production НЕ установлено. Провайдер не выбран, аккаунт не создан.

## Как работает

- `scripts/operations/independent_offsite_push.sh` раз в сутки, после ночной
  копии, берет самую новую копию со статусом `verified`.
- Поток `tar | age -r <получатель> | rclone rcat`: на диск и к провайдеру
  открытый текст не попадает. Сервер знает только публичный получатель age;
  ключ расшифровки на сервере не хранится.
- После выгрузки объект скачивается назад, его SHA-256 сравнивается с
  отправленным. Только после совпадения пишется подтверждение
  `<RUN>.signed-backup.tar.age.json`.
- Скрипт ничего не удаляет и никогда не перезаписывает существующий объект.
  Объект без подтверждения считается неудачной выгрузкой и требует ручной
  проверки.
- Статус пишется в `independent_status.json` (`ok`, `running`, `failed`).

Проверено тестами (`tests/test_independent_offsite.py`,
`tests/test_backup_wrapper_minio.py`): расшифровка дает те же байты; маркер
открытого текста не встречается в данных провайдера; повторный запуск ничего
не меняет; ключи выгрузки не могут удалять; невыверенная копия не
выгружается; обрыв выгрузки не засчитывается; устаревшая и испорченная копия
обнаруживаются; ошибка дает ненулевой код выхода.

## Требования к провайдеру

- Другая компания, не Yandex, и S3-совместимый API (rclone).
- Версионирование бакета или Object Lock, чтобы испорченную или
  перезаписанную копию можно было вернуть.
- Отдельные ключи: для выгрузки только list/get/put; ключ удаления (для
  срока хранения) хранится не на VPS.
- Оплата, доступная владельцу. Варианты для сравнения (аккаунты не созданы,
  цены уточнить на сайте): Selectel S3, VK Cloud S3 (оплата в рублях),
  Backblaze B2 (Object Lock, оплата картой иностранного банка).

Объем: около 92 МБ зашифрованных данных в сутки, около 2,8 ГБ за 30 дней без
удаления старых копий. Срок хранения задается правилом жизненного цикла у
провайдера (например, 60 дней), а не этим скриптом.

## Установка (после решения владельца, отдельным релизом)

1. Установить `age` на VPS: `apt install age` (версия 1.1.1 в Ubuntu 24.04).
   Это изменение production, требует отдельного согласования.
2. Бакет с версионированием; пользователь с правами только list/get/put.
3. `/root/.config/rclone/independent.conf`, права 0600. В описании remote
   обязательно `no_check_bucket = true`: иначе rclone пробует CreateBucket и
   ключ без этого права получает 403.
4. Получатель age: `~/DenisStock-Recovery/keys/recipient.txt` (публичный, не
   секрет) в `/etc/denstock/independent-recipient.txt`.
5. `/etc/denstock/independent-offsite.env`, права 0600:
   `INDEP_TARGET`, `INDEP_RCLONE_CONFIG`, `INDEP_RECIPIENT_FILE`,
   `BACKUP_ROOT=/opt/denstock/backups`.
6. systemd-таймер через 2 часа после ночной копии. Первый запуск вручную,
   затем проверка с Mac:

```bash
scripts/operations/independent_offsite_check.sh --target <remote>:<bucket>/denstock --config <файл только для чтения> --deep
```

## Проверка свежести и оповещение

`independent_offsite_check.sh` запускается НЕ на VPS (на Mac владельца или
втором сервере), чтобы обнаружить и смерть VPS: коды выхода 0 FRESH, 2 STALE
или нет копий, 1 CORRUPT или провайдер недоступен. Порог по умолчанию 26
часов. Раз в неделю запускать с `--deep`.

## Восстановление из этой копии

Скачать объект и подтверждение, сравнить SHA-256, затем
`scripts/dr/prepare_kit_restore.sh` (ветка `claude/offline-full-service-restore`):
формат объекта тот же, что у комплекта. Доказано прогоном
`INRUN=1 KIT_MODE=1 scripts/dr/synthetic_drill.sh`.
