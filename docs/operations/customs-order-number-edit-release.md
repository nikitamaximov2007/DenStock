# Отдельный выпуск: исправление номера таможенного заказа

Кандидат готовится в ветке `codex/customs-order-number-edit-20261026` от
последнего подтверждённого web-кода `741b65c686624dc5a2f5ec5629019af924e13407`.
Перед выпуском проверить фактический runtime SHA через image identity и
интегрировать кандидат поверх него, если production изменился. Ветка быстрых
действий в этот выпуск не входит.

## Объём и данные

- Меняется только `web`. Боты, каталог, Caddy и PostgreSQL не пересоздаются.
- Миграция `customs_orders.0005_customsordernumberchange` добавляет пустую
  таблицу истории. Существующие заказы и строки не переписываются.
- Номер хранится в `CustomsOrder.number`, внутренний `id` не меняется.
  Уникальность `(order_type, number)` и положительность номера уже защищены БД.
- Исправление фиксированного заказа делает атомарное обновление только колонки
  `number` и запись старого и нового номера, пользователя и времени. Снимки
  строк, финансовые значения, статус, автор и дата создания не меняются.
- Ссылки приложения используют `pk`. Имя повторно скачанного XLSX будет новым;
  ранее выгруженные файлы и любые внешние ссылки, записавшие старый текстовый
  номер, автоматически не обновятся.

## Ворота выпуска

1. Получить отдельное разрешение владельца и согласованное тихое окно.
   Проверить фактический web SHA, образ, OCI revision, здоровье сервисов,
   активные операции и миграции. Сохранить прежний web image ID и Compose
   overlays.
2. Создать полный подписанный PRE без ротации: PostgreSQL, public media и
   private media. Зашифровать age на Mac, проверить Ed25519 и SHA-256,
   восстановить PostgreSQL 16 и оба дерева файлов в изоляции.
3. Установить одобренный образ только для web. Штатный entrypoint применяет
   миграцию; не запускать её вручную второй раз. Проверить лист миграций,
   runtime SHA, `/healthz/`, HTTPS и анонимный 404 для private media.
4. Без изменения production-данных открыть существующий заказ, список и
   скачать его XLSX. Не менять номер настоящего заказа ради теста.
   Сверить число заказов и строк, остатки и финансовые итоги с PRE, учитывая
   только отдельно объяснённые фоновые записи.
5. Создать отдельный полный подписанный POST без ротации. Проверить подпись,
   хеши и изолированно восстановить PostgreSQL 16 и оба media-каталога.

При ошибке остановиться и установить текущую схему и состояние данных.
Не удалять таблицу аудита и не выполнять автоматический откат миграции после
реальных исправлений номера. Старый совместимый web-образ можно рассматривать
для app-only возврата после проверки, но старую БД поверх текущей не
восстанавливать без отдельного решения владельца.
