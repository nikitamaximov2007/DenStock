# Закреплённые ячейки деталей

`PartPreferredLocation` хранит одну предпочтительную ячейку для карточки
детали. Это самостоятельная подсказка для новой приёмки, а не остаток, лот,
резерв или складское движение.

## Правила

- Успешная приёмка, положительная корректировка, возврат и перемещение обновляют
  закреплённую ячейку в той же транзакции, что и реальная складская операция.
- Продажа, списание, выдача в ремонт и уменьшение остатка не удаляют закрепление.
- При нескольких текущих ячейках приёмка показывает все физические варианты и
  требует выбор. Последняя подтверждённая ячейка может быть только подсказкой.
- Архивная или запрещённая ячейка остаётся в истории закрепления, но не может
  быть автоматически выбрана для новой приёмки.

## Первичное заполнение

После применения миграции сначала выполните только анализ:

```powershell
python manage.py backfill_preferred_part_locations
```

Команда ничего не пишет без `--apply`. Она выбирает единственную текущую
физическую ячейку как самый сильный источник. Если текущего остатка нет, она
использует последнее подтверждённое движение с ячейкой назначения. Детали с
несколькими текущими ячейками остаются без единственного закрепления и выводятся
счётчиком и несколькими ID в отчёте.

После проверки агрегатов выполните:

```powershell
python manage.py backfill_preferred_part_locations --apply
```

Команда не изменяет лоты, `StockBalance`, резервы, документы или
`StockMovement`. Она не переписывает уже созданные закрепления, поэтому повторный
запуск безопасен.
