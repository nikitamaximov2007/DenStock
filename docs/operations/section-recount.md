# Пересчёт участка хранения

## Назначение

«Пересчёт участка» предназначен для полной сверки всех активных ячеек выбранного
canonical V2-ящика без использования приёмки и без создания фиктивного
количества на этапе ввода. Адрес ящика имеет вид `S03-D02`; состав документа
берётся из его дочерних `StorageLocation` типа `cell`. Никакие отсутствующие
V2-ячейки автоматически не создаются. Старый фиксированный участок временно
сохраняется только как совместимый fallback до явной миграции адресов.

## Порядок работы

1. Откройте «Склад» - «Инвентаризация» - «Пересчёт участка».
2. Выберите ящик, создайте документ и нажмите «Начать пересчёт». После старта
   все его активные ячейки блокируются для приёмки, перемещения, продажи, резерва, ремонта,
   возврата, списания и других складских проводок.
3. Выберите ячейку и сканируйте детали. Каждая строка хранит точный артикул и
   фактическое количество. Количество также можно исправить вручную или удалить.
4. Завершите каждую ячейку. Для детали из нескольких партий распределите факт
   по партиям и статусам `available`/`quarantine` явно. Допускаются только
   партии с зафиксированной себестоимостью и фактически присутствующие лоты из
   snapshot; система не угадывает себестоимость и не создаёт новую партию.
5. Нажмите «Подготовить dry-run», проверьте расхождения и нажмите «Применить».

## Пересчёт одной ячейки

Повседневный режим использует тот же документ, snapshot, fingerprint, durable
lock, распределение по партиям и atomic apply. Он не привязан к
конкретному ящику: целевой набор состоит из одной выбранной активной ячейки.

1. Откройте карточку ячейки и нажмите «Пересчитать ячейку».
2. Проверьте системное количество позиций и единиц, затем нажмите
   «Начать пересчёт». С этого момента складские изменения ячейки заблокированы.
3. Сканируйте штрихкод или точный артикул. Один скан добавляет одну единицу.
   Деталь также можно найти по названию, количество можно исправить, ошибочную
   строку удалить.
4. Нажмите «Я закончил пересчёт», затем «Проверить расхождения».
5. Dry-run показывает для каждой детали системный и физический факт, дельту,
   недостачу и излишек. Никаких записей склада он не создаёт.
6. Только кнопка «Применить результаты» создаёт необходимые `ADJUST_OUT` и
   `ADJUST_IN`. Совпавшие лоты не перепроводятся и движений не создают.

Новый излишек можно связать только с финансово закрытой партией с сохранённой
себестоимостью. Общий физический остаток после применения не может превысить
количество строки партии. При неоднозначной партии или статусе
`AVAILABLE`/`QUARANTINE` требуется явный выбор. Поштучные экземпляры этим
количественным workflow не изменяются: если они находятся в ячейке, запуск
останавливается с понятным сообщением.

## Удаление и архивирование ячейки

В карточке ячейки опасное действие открывает отдельный read-only preflight.
Hard delete доступен только новой пустой ячейке без единой связи с документами,
остатками, движениями, пересчётами или preferred location. Для исторической
пустой ячейки доступно только архивирование: `is_active=False` и
`storage_allowed=False`, все FK и история остаются. Физический, доступный или
зарезервированный остаток, активный пересчёт и активные вложенные места
блокируют оба действия. Для подтверждения пользователь вводит точный код.

До применения сканы, ручные правки, завершение ячейки и dry-run не изменяют
остатки, резервы, лоты или журнал движений. Активные резервы блокируют
подготовку и применение и показываются с деталью, лотом, ячейкой, количеством
и заказом. Применение выполняется одной
транзакцией через существующий inventory service. Старые движения, стоимость
партий, продажи и их snapshot не переписываются.

## Безопасность

В документе сохраняются автор, времена, исходный snapshot и его fingerprint.
Fingerprint включает идентичность и доступность ячеек, остатки, резервы,
статусы лотов и партий, а также предпочтительные ячейки деталей. Если любое
из этих состояний изменилось после snapshot, применение полностью откатывается
и документ получает статус «Ошибка». Row-lock ячеек захватывается до snapshot,
а складские проводки повторно проверяют durable lock. Повторный вызов
завершённого apply идемпотентен. Отменить можно черновик, пересчёт, готовый или
ошибочный документ; после начала apply отмена запрещена.

Доступ имеют администратор, руководитель и кладовщик с возможностью
`manage_stocktaking`. Производственные данные для этого workflow изменяются
только после явного подтверждения применения.
