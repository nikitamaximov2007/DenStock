# Messenger Customer Cabinet V1

Текущая продуктовая модель PRO-STOR: сайт остаётся анонимным, а Telegram и
MAX являются границей идентичности клиента.

## Статус web-account

`CUSTOMER_ACCOUNT_ENABLED=false` и `CUSTOMER_AUTH_MAX_ENABLED=false`.

Web Customer Account V1 не активирован. Его код и миграции остаются в проекте
как отложенная возможность:

**WEB CUSTOMER ACCOUNT V1 - DEFERRED / NOT ACTIVATED**

## Messenger cabinet

В Telegram и MAX доступны:

- «Мои заявки» — только заявки, связанные с конкретным provider user id;
- «Мои покупки» — только проведённые `Sale`/`SaleLine` клиента;
- детализация покупки;
- «Повторить покупку» через текущий preview.

Имя, username, телефон и display name не доказывают владение и не используются
для объединения клиентов. Покупки доступны только после явной связи
`CustomerIdentity` с карточкой DenisStock `Customer`.

Повторная покупка каждый раз заново проверяет текущую публичность, активность,
остаток и общий канонический customer-price resolver. Историческая
`SaleLine.unit_price` показывается только как история и никогда не становится
текущей ценой. Неизвестная цена отображается как «Цена уточняется», а не как
`0 ₽`.

Нажатие «Создать заявку» создаёт новую `CustomerRequest` после повторной
валидации. Заявка не является покупкой, резервом, оплатой или движением склада.

`CustomerAccount` и `CustomerIdentity` используются как нейтральная внутренняя
инфраструктура владения. Отдельный флаг
`CUSTOMER_MESSENGER_CABINET_ENABLED` управляет только кабинетом в ботах.
Web-флаги остаются независимыми: при
`CUSTOMER_MESSENGER_CABINET_ENABLED=true`,
`CUSTOMER_ACCOUNT_ENABLED=false` и `CUSTOMER_AUTH_MAX_ENABLED=false` сайт и
браузерная авторизация остаются выключенными.

История ограничена последними 12 месяцами и сортируется по `sold_at`, затем по
ID продажи. Проведённые складские возвраты уменьшают количество, доступное для
повтора; исторические продажи не изменяются. Источник повторной заявки —
`messenger_repeat`.

Подтверждение повтора дополнительно требует явно настроенную утверждённую
версию согласия `CUSTOMER_MESSENGER_REPEAT_CONSENT_VERSION`. При отсутствии
текущего имени или телефона заявка не создаётся.

Внутренняя связь кабинета с карточкой клиента выполняется сотрудником с ролью
администратора или менеджера на `/customer-accounts/links/`: сотрудник видит
безопасный provider и provider user ID, выбирает точную карточку, а затем может
снять связь. Автоматического сопоставления по имени, телефону, username или
display name нет; снятая связь сохраняется для аудита.
