# Аудит клиентских цен на снимке продакшена, 12.09.2026

Разовый протокол проверки перед запуском PRO-STOR. Правило и порядок работы:
`docs/operations/customer-price-audit.md`. Продакшен не изменялся: снимок снят
только на чтение и разбирался в отдельном контейнере PostgreSQL 16.

## Что проверялось

```
цена клиента ₽ = оптовая цена USD × 105 × 1,40   (до целого рубля, ROUND_HALF_UP)
```

Курс и наценки в продакшене на момент снимка: `current_usd_rate = 105.0000`,
`brp_markup_percent = 40.00`, `polaris_markup_percent = 40.00`. То есть
настройки уже равны проверяемому правилу, и 100 $ дают 14 700 ₽.

## Подготовленная сверка данных

Механизм уже существует: `manage.py recalculate_linked_part_prices` (по
умолчанию dry-run). Проверено на КОПИИ снимка, продакшен не трогался.

* Изменится строк: **10**.
* Изменение цены: минимум **−1 321 ₽**, максимум **+15 385 ₽**, медиана
  **−152 ₽**. Восемь из десяти цен снижаются, две растут.
* Примеры: #684 45 000 -> 60 385 ₽; #108 6 614 -> 5 293 ₽; #59 616 -> 484 ₽;
  #445 1 364 -> 1 385 ₽.
* Кроме этого меняется только ярлык источника цены у девяти связей
  (`manual` -> `calculated`), как и задумано правилом «ручная цена не замок».
* Сравнение копии до и после: остатки, лоты, движения, продажи, строки продаж
  с их ценами, ремонты, клиенты, прайсы BRP и каталог аналогов побайтово
  совпадают; ни одно другое поле карточки не изменилось.
* Повторный аудит после сверки: PRICE_MISMATCH 0, MANUAL_OVERRIDE 0,
  EXACT_MATCH 125 889.

**Сверка не применена и не будет применена без решения владельца:** десять
цен, из них девять видны клиентам на витрине, и восемь из них снизятся.

## Публичная витрина

Публичная цена это `PartType.recommended_price`, прочитанная единственной
функцией `resolve_current_customer_price`. Своей формулы, своего поля и своей
копии цены у PRO-STOR нет: поиск, карточка, корзина, форма заявки и снимок
`price_seen` в заявке берут одно и то же число (`tests/test_customer_price_gate.py`,
сквозная проверка на живых процессах ниже). Цена, присланная браузером,
игнорируется везде.

## Как воспроизвести

```
docker compose exec -T db pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc > snap.dump
pg_restore -d <scratch> --no-owner --no-privileges snap.dump
DATABASE_URL=<scratch> python manage.py migrate
DATABASE_URL=<scratch> python manage.py audit_customer_prices --csv prices.csv
DATABASE_URL=<scratch> python manage.py recalculate_linked_part_prices
```
