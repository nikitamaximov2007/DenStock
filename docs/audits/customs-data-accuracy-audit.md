# Forensic audit: точность данных Excel для таможни

Дата аудита: 2026-08-26  
Ревизия начала аудита: `9c6ea62fafbb24847b3f840e5a651c0ddf9b8e50`

## Вердикт

**CUSTOMS DATA PARTIALLY VERIFIED.**

DenisStock не хранит и не импортирует исходный набор таможенных документов.
Функция с UI-именем «Экспорт в Excel для таможни» формирует рабочую форму
заказа из журнала складских действий и каталожных карточек. Поэтому
сопоставление с декларацией, инвойсом, VIN или первичным экспортом поставщика
невозможно: таких источников, их версий, хэшей и дат импорта в приложении нет.

Внутренняя логика строк, точный артикул, количества, возвраты, формулы,
пустые неизвестные веса и защита Excel покрыты автоматическими тестами.
Это не является подтверждением таможенной достоверности внешних реквизитов.

## Фактическая архитектура и lineage

| Выходная колонка | Фактический источник | Классификация | Ограничение |
| --- | --- | --- | --- |
| A, tracking | не заполняется системой | NOT EXPORTED | ручное поле шаблона |
| B, артикул | `WarehouseAction.part_number` snapshot | VERIFIED | точная проданная/выданная идентичность, не replacement |
| C, название RU | `PartCustomsInfo.customs_name_ru` или словарный автоперевод EN | MANUAL / DERIVED | не импортированное таможенное наименование |
| D, название EN | текущий BRP/Polaris каталог или имя Part | DERIVED | не snapshot на дату действия |
| E, производитель | snapshot действия, иначе каталог/дефолт | DERIVED / DEFAULTED | не реквизит декларации |
| F, страна | константа `CANADA` | DEFAULTED | не использует `PartCustomsInfo.country_of_origin`, неверно для Polaris и любых иных стран без доказательства |
| G/H, вес брутто/нетто за штуку | ручной `PartCustomsInfo` с URL/примечанием при наличии | MANUAL / SOURCE PROVENANCE UNAVAILABLE | URL и note не обязательны, нет неизменяемой версии источника |
| I, вес брутто суммарный | формула `J*G` | DERIVED | корректен только при корректном ручном весе |
| J, количество | активные `WarehouseAction`, repair return вычитается из repair issue | VERIFIED | это складское потребление, не таможенная партия |
| K, стоимость за штуку | текущая wholesale USD цена BRP/Polaris, допускается replacement/superseded источник | DERIVED | не invoice/declaration value, не snapshot; может меняться после действия |
| L, общая стоимость | формула `K*J` | DERIVED | зависит от текущего K |
| M, область применения | ручной контролируемый выбор или совместимость каталога | MANUAL / DERIVED | не код ТН ВЭД и не декларационный реквизит |

Следующие требуемые для внешней сверки сущности отсутствуют: номер и дата
декларации, invoice number/date/value/currency, VIN/vehicle mapping, HS/ТН ВЭД,
экспортёр, импортёр, consignor/consignee, declarant/broker, incoterms,
manufacturer/model year и raw source-file registry.

## Provenance и неизменяемость

`WarehouseAction` хранит snapshot номера, названия, производителя, количества
и времени действия. Это пригодный внутренний след для B/J и группировки.
`PartCustomsInfo` хранит редактируемые вручную веса, название, область
применения, `updated_at` и `updated_by`, но не хранит исходный файл, URL-версию,
хэш, дату получения или историю изменений. У wholesale catalog price также нет
snapshot, используемого экспортом. Следовательно доказуемая provenance есть
только у складского действия, а не у внешней таможенной семантики.

## Reconciliation

В репозитории единственный customs XLSX это layout-template
`apps/actions/customs_template/supplier_order_template.xlsx`. Raw source
dataset, CSV/XLSX декларации или import command отсутствуют. Поэтому:

- source row count: unavailable;
- source vs DB reconciliation: unavailable;
- checksum/hash comparison: unavailable;
- duplicate/missing records relative to source: unavailable;
- по строкам системы: тесты подтверждают grouping exact identity, cancellation
  exclusion и repair-return netting, но не внешний факт поставки.

## Подтверждённый дефект доступа и исправление

Колонка K содержит wholesale USD price. До исправления endpoint
`actions_export` проверял только возможность провести sale/reserve/repair,
поэтому продавец без `can_view_purchase_cost` мог скачать закупочную цену.

Исправление требует `can_view_purchase_cost` дополнительно к доступу к экрану.
Регрессия `test_export_requires_purchase_cost_permission` закрепляет ответ
403 для роли «Продавец/Мастер». Расчёты, source mapping и бизнес-логика
экспорта не изменены.

## Изолированная UI-проверка

На локальной SQLite QA-базе создана одна синтетическая BRP-строка:
`QA-219800345`, quantity 2, gross 0.500 kg, net 0.400 kg, application
«СНЕГОХОД», wholesale 28.15 USD. Отрисованный экран отчёта показал:

- строку готовности `1 / 0`, артикул, оба веса и вычисленный gross total
  1.000 kg;
- явный status «Вес подтверждён вручную»;
- на детальной форме label «Источник веса: Получено из источника» и
  «Источник в текущем экспорте: Указано вручную»;
- при ширине 390 px нет horizontal overflow документа (`scrollWidth ==
  clientWidth`), а широкие таблицы имеют собственный горизонтальный scroll.

Это визуальная проверка поведения интерфейса, не доказательство достоверности
внешних таможенных фактов. Использовались только локальные QA-объекты.

## Риски, которые остаются блокирующими для утверждения внешней точности

1. **P0: отсутствует source of truth.** До передачи первичного таможенного
   dataset нельзя утверждать точность страны, стоимости, веса, названия и
   области применения.
2. **P0: страна производства всегда `CANADA`.** Это явно задано в exporter и
   покрыто прежним тестом. Для Polaris или источников не из Канады значение
   не имеет доказуемой связи с данными детали. Не менять автоматически без
   согласованного первичного источника и migration/data-repair плана.
3. **P1: USD стоимость является current catalog value.** Она не является
   исторической invoice/declaration value и replacement может быть источником
   только цены. Повторный экспорт той же операции способен дать иную сумму.
4. **P1: ручные веса не имеют обязательной provenance.** `weight_verified`
   подтверждает ручной ввод, а не верификацию внешним документом.
5. **P1: capacity.** Шаблон содержит 140 рабочих строк (10-149), а exporter
   не проверяет количество grouped rows до записи. Экспорт свыше лимита надо
   отдельно защитить явной ошибкой или расширяемым шаблоном.

## Минимальный безопасный следующий этап

Передать изолированный, обезличенный raw customs dataset либо формально
описанный источник. После этого можно определить canonical key, импортировать
версионированные записи в отдельную неизменяемую сущность, связать их с Part
и провести требуемую row-level сверку. До этого корректное обозначение функции
в документации и релизных материалах: «складская форма заказа с вручную
поддерживаемыми таможенными полями», не «проверенный экспорт декларации».
